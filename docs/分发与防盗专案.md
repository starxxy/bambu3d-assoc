## 1. 定价

### 1.1 定位判断

这是「普通缩略图生成补丁」，不是重型商业软件。买它的动机是「让 Bambu Studio 的 3D 文件在资源管理器里有预览」。这类工具的天花板不高，靠单卖 exe 不赚钱。所以：

- **软件本身走轻定价 / 免费引流**，目的是拿到用户联系方式与机器码，把价值转移到**模型包与持续更新**。
- 收费重心放在「模型包 / 商用授权 / 多机」上，软件本体只是入场券。

### 1.2 推荐分档（结合「绑定更新与模型」的防盗逻辑）

| 档位 | 内容 | 建议价 | 说明 |
|---|---|---|---|
| 免费 / 试用 | 缩略图功能全开，但导出封面带「水印」或限数量；更新与模型需付费 | 0 元 | 拉曝光、拉联系方式、拉机器码 |
| 基础版（买断） | 去水印、解锁全量更新、单台机器 | ¥9.90 首发 → ¥29 正式 | 获客价，买断单机 |
| 进阶 | 多机（2 台）/ 商用授权 / 模型包订阅 | ¥49–99 | 拉客单价，覆盖团队/商用 |
| 模型包 | 持续更新的打印模型（台灯、小灯、烟盒等可定制件） | 按包定价 | 真正的复购来源 |

### 1.3 付费动机设计

- 免费层「能看缩略图，但想要无水印 / 多格式 / 新模型必须解锁」——用免费功能证明价值，用锁住的增量逼付费。
- 每次出新版/新模型都强调「已激活才自动更新」，让「没买」的人持续看到差距。

## 2. 在线激活（一码一机，可吊销）

### 2.1 机器码获取（客户端）

机器码不直接采集 MAC（易变、易被虚拟机搞乱），用「相对稳定且可人工描述」的组合：

- `GetComputerNameExW(ComputerNameNetBIOS)` 机器名（归一化大写）
- `WMI: Win32_BIOS.SerialNumber` 或 `Win32_BaseBoard.SerialNumber`
- 取「系统盘序列号」做兜底

客户端算出 `machineCode = SHA1(机器名 + BIOS序列号)` 前 16 位，展示给用户。这样换硬盘/重装不影响，同型号机器几乎不会撞。

### 2.2 授权码签发（服务器端）

- 用你本机持有的**RSA 4096 私钥**离线/在线签发，私钥**只在你机器或 VPS 的受控目录**，绝不进安装包、不进 Git、不进公开仓库。
- 授权码 = `licenseId + 有效期 + 允许的 machineCode + 档位 + 签名`，做 RSA 签名；客户端用**内置的公钥**验签，私钥永远不出门。
- 服务端存一份「已发码记录」：licenseId / machineCode / 邮箱或 QQ / 时间 / 档位 / 状态（可吊销），这就是追溯 + 售后 + 转化入口。

### 2.3 激活流程

1. 用户安装后，管理器「激活」页显示本机机器码。
2. 用户把机器码发给你（或直接走你的自动发码 API，见第 3 节）。
3. 服务端签发授权码返回；客户端拿到后：
   - 用内置公钥验签；
   - 校验 `machineCode` 与本机一致；
   - 存到 `%LOCALAPPDATA%\Bambu3DAssoc\license.dat`（按安装 scope 也可放 HKCU 注册表）。
4. 启动时校验一次 + 本地缓存有效则免联网；定期（如 7 天）静默回服务器查「是否被吊销」。

### 2.4 吊销与一码一机

- 服务端标记某 licenseId 为「已吊销」，客户端下次联网回查时自动失效 → 这是「防私下传播」的硬闸。
- 同一 machineCode 只发一份基础版；要多机/商用走进阶档。
- 客户端保留「离线宽限期」：吊销只在能联网时生效，断网期间宽限 N 天，避免误伤。

## 3. 服务器端自动化分发（公网 Linux VPS）

目标：「购买 → 自动发码 → 自动下载 → 激活」尽量全自动。技术选型优先**简单可运维**，不堆栈。

### 3.1 选型

- **Nginx**：静态托管安装包 + `latest.json`（版本清单）+ HTTPS。
- **轻量应用**：一个 Python（Flask/FastAPI）或 Node 服务，只做 3 件事：发码 API、激活校验 API、吊销查询。
- 数据库用 SQLite 起步（单 VPS 足够，省运维），量大再迁 Postgres。
- HTTPS：Let's Encrypt（certbot）免费证书，自动续签。

> 若你更熟另一套（如已有宝塔/1Panel 面板），用面板等价实现也行，原则是「Nginx 静态 + 一个发码/校验接口 + SQLite + 自动证书」。

### 3.2 目录与接口

```
/www/bambu3d/
  index.html            # 下载页（购买入口）
  downloads/
    Bambu3DAssoc-Setup-1.2.4.exe
    license-public-key.pem     # 只发公钥
  api/
    /issue      POST {machineCode, contact}      -> {license, expires, tier}
    /activate   POST {license, machineCode}      -> {ok, revoked?}
    /revoke-check GET  ?license=                 -> {revoked: true/false}
    /latest     GET   -> {version, url, sha256}
  data/
    db.sqlite3            # 发码记录 / 吊销状态
    keys/
      license-private.pem # RSA 私钥（受控，绝不公开）
```

### 3.3 自动化清单

- 发码：`POST /issue` 校验机器码格式 → 用 `license-private.pem` 离线签名 → 落库 → 返回授权码。**全程无人工介入**。
- 下载：`/latest` 返回当前版本与 `sha256`，客户端下载后校验（复用 `envcheck.cpp` 的 `sha256Hex`）。
- 更新检查：客户端读 `license.dat` 里的版本，比 `/latest` 决定下载；模型包同样走 `/latest` 的模型通道。
- 吊销：后台把某 licenseId 标记吊销，客户端下次回查即失效。

### 3.4 安全要点

- 私钥 `license-private.pem` 只存 VPS 受控目录 + 你本地备份，**绝不进 Git / 安装包 / 公开**。
- 发码记录（谁、什么机器码、什么档位）是你追溯 + 售后 + 转化的底表。
- 下载页可只暴露「购买后才给下载链接」，降低安装包被随便白嫖的概率。

## 4. 防私下传播：措施排序（结合「绑更新」）

| 序 | 措施 | 作用 | 成本 |
|---|---|---|---|
| 1 | 在线激活（2.2/2.3） | 拿到 exe 也激活不了，转发即废 | 中 |
| 2 | 一码一机 + 可吊销 | 限制传播面 + 可随时收回 | 低 |
| 3 | 把价值绑在更新/模型（3.3 更新检查 + 模型包） | 旧版共享出去自动贬值，想用新的必须回你这 | 中（持续更新即可） |
| 4 | 发码记录 + 联系方式 | 追溯 + 售后 + 心理震慑 | 低 |
| 5 | 版权声明 + 下载页不公开 | 对普通用户心理震慑 | 极低 |

**明确不做（当前阶段净亏损）：**
- 联网强绑 DRM / 强制登录（违背「离线补丁」定位，劝退用户）。
- 重加密防逆向（成本高，防君子不防小人）。
- 把「离线」卖点牺牲掉去换版权保护。

> 你缺的是曝光不是版权收入——让旧版「能用但旧」，比让旧版「不能用」更能把人拉回来。

## 5. 实施步骤（验收标准）

**阶段 1：激活与发码做通**
- [ ] 客户端「激活」页：显示机器码、输入授权码、验签、存 `license.dat`。
- [ ] VPS 上线 `/issue` `/activate` `/revoke-check`，SQLite 落发码记录。
- [ ] 验收：合法机器码能签发并激活；同一机器码第二次发基础版被拒；吊销后 7 天内客户端失效。

**阶段 2：下载与更新挂上**
- [ ] Nginx 托管安装包 + `latest.json`；客户端「检查更新」走 `/latest`。
- [ ] 验收：客户端能拉最新版、校验 sha256、提示有新模型包时给出更新入口。

**阶段 3：模型包 + 进阶档**
- [ ] 模型包走独立 `/latest` 模型通道；进阶档（多机/商用）在发码 API 区分档位。
- [ ] 验收：进阶档可发 2 台；模型包更新只在已激活机器上自动。

**阶段 4：打磨**
- [ ] 购买页、自动发码、离线宽限、吊销通知文案。
- [ ] 验收：从「看到广告」到「用上模型包」全链路无需你手动发码。

### 7.2 算法（已定死，两实现一致）

> ⚠️ **本仓库为公开仓库，`src/license.cpp` 中的密钥已脱敏**（数组以占位符替代）。
> 该机制自 v1.3.0 起已退役、不参与编译，保留此处描述仅为记录历史设计。

```
code(D) = CrockfordBase32( HMAC-SHA256(secret, "B3D1|" + YYYYMMDD)[0..10) )  →  XXXX-XXXX-XXXX-XXXX
```
- secret = 32 字节，XOR 混淆内置于 `license.cpp`（`kSecretXor ^ kSecretMask`）。
- Crockford Base32 无 I/L/O/U，用户手输混淆自动纠正（I/L→1、O→0、U→V）。
- 校验容差 ±1 天（跨午夜可用）；大小写/横杠/空格不敏感。
- 激活令牌 = HMAC(secret, "ACT|" + 机器名) 前 16 字节 hex，存 HKCU `Software\Bambu3DAssoc\Activated`——注册表值拷到别的机器无效（换机器/改机器名需重新兑换）。
- 试用起点 = 首次运行（exe 或 DLL 任一先跑都算），`TrialFirst`/`TrialLast` 存 HKCU；记录 `TrialLast` 高水位，**系统时钟回拨不能延长试用**。
- 30 天试用为常量 `kTrialDays`（license.cpp）。

### 7.3 日常发码流程（你手上的操作）

```
build\Release\redeem_gen.exe                 → 打印今天的码，发给要激活的用户
build\Release\redeem_gen.exe 20261001        → 指定日期（用户说后天到期就发后天的）
python tools\redeem_check.py                 → Python 侧复核（可选）
```
用户拿到码 → 管理器「激活」按钮 → 输入 → 立即生效（自动清 Explorer 缩略图缓存，占位图当场换回真图）。

### 7.4 行为细节（验收已过）

- 编译：bs3d_thumb.dll / bs3d_assoc.exe / redeem_gen.exe 全部零错误。
- 试用期外：3MF/STL 等缩略图显示灰底「试用已结束」占位卡；激活后刷新即恢复。
- 占位图不写 thumbcache（本库缓存），Explorer 磁盘缓存由启动自检/激活成功时清一次（`ExpiredCacheSwept` 标记防重复清）。
- 安装期 `/auto-apply` 不拦截（试用从装完起算）。
- 换机器 = 换机器名 → 令牌失效，需重新兑换当日码。

### 7.5 已知边界（明说，不藏）

- 这是「防君子」方案：secret 在二进制里（虽经混淆），有心人逆向可自行生成码。共享的码**只对当天有效**，无法批量长期传播——这就是本方案的设计目标。
- 1.2.4 → 1.3.0 发版时记得：改 `registry.cpp` 的 `kVersion`、`Bambu3DAssoc.iss` 的 `MyAppVersion`，重跑 ISCC。
- 若日后要升级在线激活（吊销/溯源/自动发码），v1.0 的第 2、3 节方案仍可回退启用。
